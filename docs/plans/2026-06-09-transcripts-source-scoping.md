# Earnings-Call Transcript Source Scoping — 2026-06-09

**Status:** decision doc, no code changed.
**Problem:** `lib/transcripts/fetch.ts` chain (cache → API Ninjas → Motley Fool scrape → EDGAR 8-K) is brittle: API Ninjas is paid-gated (silent fail without key), the Motley Fool scraper breaks on HTML changes, and EDGAR 8-K yields press-release text, not call transcripts. Consumers: Security Detail transcripts panel + earnings preview/recap composer (prior-quarter context, best-effort).
**Need:** ~10–30 full US-equity transcripts per quarter (large/mid-cap + a few small caps), within ~24h of the call, single user.

All pricing/gating below was verified against the providers' live pages on **2026-06-09** (not training data). Where a claim could not be verified, it's flagged.

## Headline finding

**Alpha Vantage's `EARNINGS_CALL_TRANSCRIPT` endpoint is on the FREE tier.** Several third-party reviews claim "Alpha Intelligence" endpoints are premium-only — that is wrong for this endpoint. Verified two ways against alphavantage.co directly:

1. The live demo query (`function=EARNINGS_CALL_TRANSCRIPT&symbol=IBM&quarter=2024Q1&apikey=demo`) returns a complete transcript: 28 speaker-attributed segments with name, title, full content, and a per-segment LLM sentiment score.
2. The official docs HTML badges endpoints explicitly: `INTRADAY`, `MACD`, `Realtime Bulk Quotes`, etc. are marked **Premium**; **Earnings Call Transcript is marked "Trending" — no Premium badge**. Docs state coverage of "any quarter since 2010Q1" ("over 15 years of history"), parameters `symbol` + `quarter` (fiscal, `YYYYQM` format).

Free-tier limits: **25 requests/day, 5/min** — trivially sufficient for 10–30 transcripts/quarter given the existing SQLite cache (each transcript is fetched once, ever).

## Recommendation: Alpha Vantage free tier (primary), keep EDGAR as floor

Adopt **Alpha Vantage `EARNINGS_CALL_TRANSCRIPT`** as the first external source in the chain. It is the only option that is simultaneously $0, full-text, speaker-segmented, officially supported (not a scraper), and far inside rate limits for this workload (25/day vs ~30/quarter, all cached). It even supplies per-speaker sentiment, which maps onto the existing `sentiment_score`/`sentiment_label` columns that the Motley Fool/EDGAR paths leave null.

**Pre-adoption verification (30 minutes, do before wiring):** claim a free key and probe (1) a recent quarter for a held mid-cap within 24–48h of its next call — latency is the one unverified claim; (2) two or three held small caps (e.g. recent quarters) for coverage; (3) one non-calendar-FY name (AAPL) to confirm the fiscal-quarter mapping behavior. If latency proves slow (>24h), the earnings-recap composer keeps degrading gracefully to EDGAR same-day press releases — the panel and the chat tool still gain full transcripts a day or two later, which is the current behavior's best case anyway.

**Runner-up: API Ninjas Developer @ $39/mo** (not Business @ $99 — the TODO's price assumption was off; basic full-text transcript access comes with any paid plan, and `fetch.ts` already generates its own summary/guidance/risk-factors so the Business-tier extras are unnecessary). This is the zero-code-change option: set the existing `API_NINJAS_KEY` and the current pipeline lights up. Choose it only if the Alpha Vantage probe fails on coverage or latency. Honorable mention: EarningsAPI Pro @ $24.99/mo is cheaper and claims hours-fast transcripts, but it's an unproven micro-vendor — trading one brittleness (scraper) for another (vendor risk) isn't worth $14/mo of savings over the runner-up.

Either way, **drop the Motley Fool scraper from the chain** once a stable source is live (keep the file; stop calling it), and keep EDGAR 8-K as the terminal fallback.

## Code changes for adoption (Alpha Vantage)

One new client + one insertion point, mirroring the existing API Ninjas pattern: add `lib/apis/alpha-vantage.ts` exporting `isAlphaVantageConfigured()` + `getEarningsTranscript(ticker, year, quarter)` that builds `quarter=${year}Q${quarter}` (note: AV quarters are *fiscal*; the app's `getMostRecentQuarter`/`deriveFilingReportingQuarter` are calendar-quarter, which already under-match non-calendar-FY tickers — same safe failure mode, document it), fetches `https://www.alphavantage.co/query?function=EARNINGS_CALL_TRANSCRIPT&...`, joins the `transcript[]` array into one body (`"${speaker} (${title}): ${content}"` paragraphs), derives `participants` from distinct speakers, and averages segment sentiments into `overall_sentiment`. In `fetchTranscript` (`lib/transcripts/fetch.ts`), insert it as step 2 ahead of (or replacing) the API Ninjas block, upserting with `source: "alpha_vantage"` and `source_key: alpha_vantage:${ticker}:${year}:${quarter}` — `generateSummary`/`extractGuidance`/`extractRiskFactors` already handle the rest, and the cache/`getTranscriptForChat` layers need no changes. Thread `ALPHA_VANTAGE_API_KEY` through the standard four Electron touchpoints (`AppSettings`, `bootstrapFromEnvLocal`, `getSanitizedSettings`, `electron/main.ts::startServer`) plus an optional `SettingsModal` field, per the `PUSHOVER_*` precedent. A naive 5-req/min throttle isn't needed given single-transcript, cache-first usage, but a 25-req/day soft counter logged on exceed would be cheap insurance.
