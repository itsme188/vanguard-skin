# Architectural Decisions

Record of WHY architectural choices were made. Consult before making structural changes.
Add new entries at the bottom.

---

- **PDF parsing via Claude API, not OCR** — Vanguard PDFs are image-heavy. The Anthropic SDK sends PDF pages to Claude for structured extraction. More accurate than tesseract/pdftotext and worth the API cost (~$0.50-0.80 per statement with Opus 4.7).

- **SQLite over Postgres** — Local-first, single-user app. No need for a database server. WAL mode handles concurrent reads during imports.

- **OCC format for option symbols** — Bare tickers like "INTC" collide with the underlying stock in `securities` UNIQUE(symbol) constraint. Always use full OCC format (e.g., `INTC  260320P00045000`). Three-layer fix: (1) `ensureOCCSymbol()` in parser auto-converts, (2) `upsertSecurity()` type conflict guard, (3) `buildOCCSymbol()` utility. Pattern: underlying padded to 6 chars + YYMMDD + C/P + strike*1000 padded to 8 digits. This was a painful bug — do not revert.

- **Bond par adjustment in two places** — Both market value AND cost basis need /100 for bonds. Fixed wrong multiple times. Canonical logic is in `adjustedMarketValueSQL()` in `lib/valuation.ts`.

- **Deterministic source_key for idempotent imports** — Every record gets a hash-based key so re-importing the same file is a no-op. Do not change the hashing logic without understanding the dedup implications.

- **Thematic factor exposure — separate table, query-time inheritance** — `security_factors` is standalone (not bolted onto `securities`) because factors are opinionated macro assessments, not security identity. Options inherit factors at query time via `LEFT JOIN securities u ON u.symbol = s.underlying_symbol` + `COALESCE(sf.col, sf_u.col)`. Constants/labels/colors shared from `lib/factors.ts`. Auto-classify uses Sonnet 4 with training examples.

- **Sampling strategy per API call** — (1) Chat: Opus 4.7 + adaptive thinking (temperature locked at 1.0, `effort: high`); (2) PDF extraction: Opus 4.7 + temperature 0 (determinism for structured JSON); (3) Factor classification: Sonnet 4 + temperature 0.2 (categorization with training examples). When thinking is enabled, the API requires temperature=1.0.

- **TWS singleton on globalThis** — Module-level `let` variables reset on Turbopack HMR reload, orphaning TCP sockets. `lib/tws/client.ts` stores all TWS state on `globalThis.__tws_*` properties.

- **Single dev server rule** — NEVER run two `next dev` processes against the same project directory. Turbopack's persistent cache is single-writer; concurrent writes corrupt SST files. `.claude/launch.json` is pinned to port 3099 (same as launcher) so only one server runs.

- **Transaction type casing** — All parsers output UPPERCASE (BUY, SELL, DIVIDEND, BUY_TO_OPEN, SELL_TO_CLOSE, etc.). Tax lot compute engine uses `LOWER(type) IN (...)` for case-insensitive matching across sources.

- **Streaming for PDF API** — `client.messages.stream()` + `stream.finalMessage()` avoids 10-min timeout on large PDFs.

- **`serverExternalPackages`** — better-sqlite3 excluded from Next.js bundling (native addon).

- **`import.meta.url` in migrate.ts** — Not `__dirname`, for ESM compat with Vitest.

- **Date formatting in SSR** — Never use `toLocaleString()`/`toLocaleDateString()` in Next.js server components (hydration mismatch); use manual formatting.

- **IBKR CSV format change (2026)** — Newer exports prepend account ID line before `Statement,Header,...` row. Parser handles both formats.

- **PDF document input** — Only supported on Sonnet/Opus, NOT Haiku (returns 404). Can't cheaply downgrade PDF parsing.

- **Vanguard PDF holdings retry** — `parseVanguardPdf()` checks if first extraction covers < 80% of `total_value`; if so, makes a second focused `callClaudeForHoldingsOnly()` call ignoring transaction pages.

- **Claude API code fences** — Always strip ` ```json ``` ` wrappers from Claude API responses before JSON.parse.

- **Tax lot compute null safety** — VMFXX money market reinvestments have null `price_per_share`/`quantity`. Compute engine filters with `AND price_per_share IS NOT NULL AND quantity IS NOT NULL`.

- **Agentic chat architecture** — Hybrid static context (~2,500 tokens) + 14 dynamic DB tools. Agentic loop: stream -> detect `stop_reason: "tool_use"` -> execute server-side -> append full `finalMessage.content` (including thinking blocks) -> re-stream. Max 8 iterations. Prompt caching reduces cost across loop iterations.

- **Earnings transcript pipeline** — Layered sources: EDGAR 8-K (free, always-on) -> Motley Fool scraping (free, on-demand) -> API Ninjas (optional paid). Seeking Alpha blocks server-side fetches (Cloudflare 403). API Ninjas earnings endpoint is Premium-only ($39+/mo).

- **Desktop launcher** — `scripts/launch-dashboard.sh` (lifecycle manager) + `scripts/VanguardDashboard.applescript` (stay-open app). Port 3099. AppleScript's `do shell script` has minimal PATH — must `export PATH="/opt/homebrew/bin:$PATH"`. Stay-open applet uses idle polling (not blocking `on run`) to avoid beach ball.

- **IBKR option parsing** — Descriptions like "AAPL 21MAR25 150.0 C" -> OCC symbols "AAPL  250321C00150000". Helper: `parseIBKROptionSymbol()`.

- **Tax lot filtering** — Year picker (pill buttons) + account picker. Uses URL searchParams for server-side filtering. Generic `FilterPills` component in `YearSelector.tsx`.

- **Options support** — `adjustedMarketValueSQL()` handles bonds (/100) AND options (*multiplier) in one function. Queries use `COALESCE(s.multiplier, 1)` since explicit INSERT NULL bypasses schema DEFAULT.

- **Chat markdown rendering** — `react-markdown` + `remark-gfm` in `MarkdownMessage.tsx`. Custom component map styled with Tailwind v4 tokens. Only applied to assistant messages.

- **TWR compute engine** — Chain-linked Modified Dietz method. Uses IBKR-provided `monthly_snapshots.twr` when non-null (stored as percentage, divide by 100). Cash flow day-weighting: `W_i = days_remaining / days_in_month`. Annualization threshold: 30 days minimum.

- **Calendar: FRED dates, not Claude dates** — Macro event dates come from FRED `releases/dates` API (authoritative — sourced from BLS, Census, Fed, ISM). Claude only provides enrichment (descriptions, consensus estimates, impact ratings). This was changed mid-build after Claude hallucinated NFP on a Saturday. Government shutdowns can shift release dates, so static JSON calendars go stale — FRED fetches live. 19 tracked FRED release IDs in `TRACKED_RELEASES` constant.

- **Calendar: WSH via raw IBApi** — IBApiNext has no WSH wrappers. Access via `(ibApiNext as any).api`. WSH JSON format is undocumented — `raw_json` column preserves responses for parser iteration. Dividends/ex-dividends filtered out (user preference — too noisy).

- **Calendar: Sonnet for enrichment, not Opus** — Macro event enrichment uses Sonnet 4.7 (structured JSON extraction, not deep reasoning). Briefing generation also uses Sonnet (analysis is substantive but doesn't need Opus-level reasoning). Saves ~5x cost vs. Opus per calendar sync.

- **FOMC dates: hardcoded, not API** — The Fed publishes the FOMC schedule a year in advance (8 meetings). FRED doesn't have a clean single release_id for FOMC meetings — it publishes multiple releases (statement, minutes, projections) around each meeting. Hardcoded approach is 20 lines, zero API calls, zero failure modes. Update once a year. Source: federalreserve.gov/monetarypolicy/fomccalendars.htm.

- **Vital Knowledge via IMAP, not API** — VK newsletters arrive via email. `imapflow` connects to Gmail IMAP, searches for `updates@vitalknowledge.net`, strips HTML, truncates to 8K chars total. Ported from Stock Contest (identical code). Integrated into briefing prompt — if VK context exists, Claude gets market commentary alongside event data. Graceful degradation: returns "" on any failure.

- **Email briefing: inline styles, not CSS** — Email clients (Gmail, Outlook, Apple Mail) strip `<style>` blocks and ignore CSS classes. All styling in `briefing-html.ts` uses inline `style=""` attributes. Midnight Portfolio theme colors translate directly to hex values. Simple markdown-to-HTML converter handles the subset Claude produces (##, **, -, paragraphs) without adding a dependency like `marked`.

- **Overview chart: daily overrides monthly on merge** — `CombinedPortfolioChart` merges monthly snapshots with daily valuations by date key. Daily data overwrites monthly on the same date (more granular/recent). Monthly fills gaps for older dates. Simpler than `EquityCurveChart`'s shape-preserving normalization because the stacked-area chart uses absolute values per account, not proportional adjustment.

- **Source URL extraction: raw_text > raw_html for Substack** — `extractSourceUrl()` checks `raw_html` first (view-in-browser regex), then falls back to `raw_text` for the Substack "View this post on the web at {URL}" pattern. This was the root cause of most missing URLs — Substack emails don't always include "View in browser" in their HTML, but always include the clean URL in the plaintext body. Ghost newsletters use `/r/{hash}` redirect links (3rd occurrence = article title). Bloomberg uses "Read in browser" (not "View in browser"). Source profiles documented in memory for future reference.

- **Manual digest email with mode parameter** — `POST /api/digest/email` accepts `mode: "today" | "since_last" | "since_date"` + `sinceDate` for flexible date ranges. Default (no mode) = last 24h for backward compatibility with launchd cron. `last_digest_sent_at` and `last_briefing_sent_at` tracked in `settings` table for "since last" mode. UI panel in Feeds tab supports both daily digest and weekly briefing to arbitrary recipients.

- **Launchd retry script** — `scripts/send-daily-digest.sh` replaces raw curl in the daily digest launchd plist. Retries 3 times with 2-minute delays in case the Electron app is still starting. `DigestCatchup.tsx` shows a banner on weekday app startup if today's digest wasn't sent.

- **Closed-position reconciliation covers statement books and options (2026-08-30)** — Landing the nightly fix that keys the Accounts tables on the per-(account, security) latest row exposed that the old per-account `MAX(as_of_date)` had been the de-facto closed-position filter for every asset class the snapshot-diff reconciler skipped: two mutual funds fully sold in May and eight options closed during August (Plaid drops them the day they close; the sell arrives with the statement weeks later) all resurrected. Rule now: (1) a statement is a complete book — anything absent from the latest statement-sourced snapshot is tombstoned at that date, any type, shrink-guarded statement-vs-prior-statement (never vs Plaid, whose books carry no bonds/funds); (2) equities as before; (3) options only when the latest live snapshot proves the source reports options at all (≥1 option row), per-class shrink guard. Bonds/funds are never live-snapshot-reconciled. Rehearsed on a DB copy before landing: exactly the 2 funds + 8 options. Rejected: landing the per-pair fix alone (visible phantom value on Accounts), and reverting to per-account MAX (drops every statement-only Treasury).
- **Own-origin `target="_blank"` in Electron opens an in-session child window (2026-08-30)** — External http/https/mailto → system browser; the app's own loopback origin → `{action:"allow"}` (child window shares the session partition, so Plaid Link works); everything else denied. Shipping an own-origin URL to Safari stranded it outside the session; denying it made Settings → Reconnect a dead click.
- **Holdings latest-keying unified (2026-08-30)** — Every read site keys "latest holdings" per (account, security) via `latestHoldingsPredicate`; the per-account and global `MAX(as_of_date)` shapes are retired (a per-occurrence static guard test enforces this). Quantity semantics were preserved per site (`> 0` stays via `includeShorts: false`), except: sites with NO quantity filter gained `!= 0` (reconciler tombstones must never surface as live positions), and chat shorts became opt-in (`getHoldingsForChat({ includeShorts })`, only the IBKR trading context passes true, with fully-gross weight math). Cash-equivalent rows carry per the Accounts precedent (the reconciler deliberately never tombstones them). Strategy detection partitions legs per account — cross-account covered calls are impossible. Rejected: keeping per-account keying anywhere (drops statement-only Treasuries/funds), and a whole-file guard allowlist (a future bad query in an allowlisted file must still fail).

- **Tombstone model: derived layer, origin-suffixed, directionally supersedable, coarsely fail-closed (2026-08-31)** — `docs/superpowers/specs/2026-08-30-reconciler-hardening-design.md` (rev 4, three Codex review rounds). A `recon:closed-equity:` row is a DERIVED fact with recorded provenance, never authority: it is justified only while a real (non-recon) holdings row exists at the same (account, `as_of_date`) — true by construction at mint time, since its date IS its reference snapshot's date. Losing that same-date evidence makes it an orphan, removed by `removeOrphanedReconTombstones` — never by a wholesale rebuild, which would silently re-land tombstones on *current* reference dates and move historical close dates in valuations and tax realization. Every new tombstone carries an ORIGIN SUFFIX recording which pass minted it (`:stmt` statement-pass, `:live` equity/option live-pass; legacy unsuffixed rows are treated as statement-grade, conservative) — supersession is DIRECTIONAL: a statement writer (import commit, recovery restore) may overwrite any tombstone, a live writer (Plaid) may overwrite only its own `:live` tombstones, because a live sync can never re-derive statement-grade closure evidence it would otherwise mask. Batch ownership is cleanup hygiene, not provenance: an import stamps `import_batch_id` on tombstones it mints, scoped to the accounts it actually imported (from `parsed.holdings`, never a wider set) — so `undoImport`/`restoreImportBatch` can remove owned tombstones, orphan-clean, and re-reconcile in ONE outer transaction; a rebuild failure refuses the whole undo rather than leaving a half-consistent book. Tax-generation invalidation is deliberately COARSE: any mutation that *could* change `computeTaxLots`' `RECONCILE_CLOSE` synthesis (tombstone mint/orphan-cleanup, same-date or newer-date live supersession, a price write at-or-before a tombstoned security's zero date, undo/restore of holdings or those prices) bumps the fail-closed generation counter, accepting documented over-bumps (e.g. up to three independent triggers firing in one live-writer transaction) in exchange for never under-bumping — a precision "dependency signature" was considered and rejected as unwarranted complexity for a counter that costs one re-run of the acceptance script when wrong. Rejected alternatives: prefix-only (non-suffixed) tombstones (loses the directional-supersession signal), wholesale tombstone rebuild on every reconcile run (moves history), and per-mutation fine-grained invalidation (the coarse doctrine already matches how the rest of the tax-generation system behaves).

- **Live print v2 slice A — armed coverage, cloud parity, the merge and prepare registries (2026-09-03)** — Slice A of `docs/superpowers/specs/2026-09-02-live-print-v2-design.md` (rev 4) built on branch `live-print-v2-a` as twelve SDD tasks, each with its own review round. The shape it settles: **arming an earnings worksheet is the coverage signal**, so an armed event now gets everywhere a held name's event is covered — on the Mac and in the Cloudflare Worker fallback — and arming starts the preparation a held name gets for free. The rulings worth keeping:
  - **Vendor EPS stays in its own column; no basis column (D1, user-ruled).** The Finnhub EPS consensus is written to `earnings_bogeys.eps_consensus_vendor`, and `eps_consensus` stays NULL on the `'finnhub'` row. `compileContracts` (`lib/print-watch/contracts.ts`, a slice B/F file) fills the adjusted-EPS expected value from the first non-null `eps_consensus` by rowid, and the design rules that A and B share no file — so the standing ruling "Finnhub EPS never fills the adjusted-EPS bogey" holds *by construction* instead of by a filter someone can later remove. The spec's `eps_consensus_basis` column was NOT added: a non-null `eps_consensus_vendor` IS the label condition, and every surface that renders the figure labels it "vendor, basis unspecified". Vendor REVENUE is deliberately NOT quarantined the same way — spec §2 rules that the Finnhub revenue consensus IS the revenue bogey, so it lands in `revenue_consensus_usd` like any other source. The `finnhub` bogey row is engine-owned: a withdrawn or foreign-listing-echoed vendor estimate deletes the row rather than leaving a stale figure feeding the revenue bogey.
  - **The Mac never writes KV (D2).** The armed-events delta reaches the cloud through a new `POST /internal/armed-events` on the Worker — the same shape as every existing Mac↔Worker marker (`WORKER_MARKER_URL` + `X-Cron-Secret`) — and the Worker does the read-compare-write on KV key `armed-events`. The generation guard therefore lives Worker-side, and a strictly-greater rule makes a replayed or out-of-order POST a reported no-op. A read-only `GET /internal/armed-events` twin exists purely so the sandbox end-to-end and the post-deploy check can see the generation that stands; it writes nothing.
  - **`armed` is a display status, never an event decision (D3, D3b/R10).** `SymbolStatus` gained `armed` with precedence `held` > `watchlist` > `armed` > `neither`, and it renders as a chip on the Today Earnings Hub, the earnings cockpit rows (R10 — an armed-only row would otherwise have read "watch", a false statement), the digest reporters block and its Worker mirror. Every *decision* about a specific print goes through `coveredForEvents` / `isEventArmed` instead. A repo guard test (`tests/repo/symbol-status-consumers.test.ts`) classifies every call site of the six helpers by effect and fails the suite on an unclassified one, on a stale entry, and on any selection-covered file that compares a status to `"armed"`.
  - **Cluster-aware armed coverage (R11).** Two calendar rows can describe one print (the same symbol on the same date from two vendors). The sweep's dedupe and the cockpit's dedupe pick *different* twins, so arming the row the user can see would otherwise fail to cover the row the engine acts on — "armed but nothing happened", the exact failure this slice exists to remove. `coveredForEvents` therefore treats an event as armed-covered when it, or any unsuperseded earnings twin sharing its `(UPPER(symbol), event_date)`, carries a flag. `isEventArmed` and `getArmedEventIds` keep their exact per-event meaning; the widening lives only in the coverage helper.
  - **Outbox durability: write in-transaction, skip no-ops, reconcile on the sweep tick, cap the post-commit wait (D8, D10, R8, R9).** Every mutation that changes the armed projection appends one `cloud_outbox` row inside its own IMMEDIATE transaction, so the row and the state it describes commit together and the generation is allocated under the write lock. An identical projection writes nothing and reports the generation that already stands (D10), which is what lets the sweep re-derive cheaply: **every earnings sweep tick re-writes the projection before draining** (R8), turning any missed un-arm path — or a state that predates the outbox entirely — into a self-heal within one tick rather than a permanent divergence. The drain sends unsent rows in generation order and stops at the first failure, so the Worker never sees N+1 before N. Mutating routes attempt an immediate push but the WHOLE wait is capped at two seconds (R9): the chained drain races a timer and, when the timer wins, keeps running in the background while the user's request returns. Never make a user wait on the cloud.
  - **Tombstone retention is two rules, OR'd (D7).** A removal is carried in every later payload while the event is still recent (event date within two ET days) **or** while the removal itself is younger than 48 hours. The nightly snapshot always lands inside that window, so a removal can never be dropped from the delta before a snapshot that omits the event exists. A tombstone is a statement that an event is NOT armed — the Worker never adds one to its armed set.
  - **A date correction carries the whole state, on every hand-back path (R12, R12b, R15, R16, R17).** `mergeEarningsEventState` folds a donor event's flags, prepare steps, scan-ledger rows, bogeys and email/skip audit into the surviving event, inside the caller's transaction and before the donor row is deleted (everything cascades). It runs on the user correction path, the automatic date reconciler, **and both delete-with-hand-back paths** (R12 the suppress-delete of a sync row, R12b the manual-row delete) — the arm must follow the print, or an arm dies with a row whose print survives. Three sub-rulings: the **preview plausibility gate applies on every merge path including the correction path** (R15) — a preview is a promise about one specific print, and dragging a stale one onto a print it could not have covered both fabricates history and blocks the genuine preview forever; the accepted cost is that a stale preview's audit row dies with its donor, while the email itself is still in the mailbox. The **destructive bogey-collision rule stands on the automatic reconcile path too** (R16): content is unioned newer-then-older so a figure only one side published survives, provenance follows the newer row only, and the sole loss is a value the newer row contradicts. And because that rule writes an explicit column list and then deletes the donor, a bogey column missing from the list would be destroyed silently — so a repo guard test (`tests/repo/bogey-merge-columns.test.ts`) pins the two lists plus the structural columns against the live schema exactly (R17). Single-sourcing those lists with the mutation module's own content list is deliberately deferred to slice F.
  - **Prepare steps: a claim ledger with a deadline (D6, R13, R14, R19).** Arming enqueues one row per registered step in `earnings_prepare_steps`; the route kicks a pass without awaiting it and the sweep tick is the durable path, re-reconciling missing rows and re-running everything runnable. Work is claimed by compare-and-set on a fresh token and finalised by CAS on that same token, so a timed-out worker's outcome can never land on top of its successor's. Three additions came out of review: every invocation carries a **four-minute deadline** and an **additive `signal: AbortSignal` on `PrepareStepContext`** (R13) — deliberately inside the five-minute stale-claim window so the owner always finalises before any takeover could occur, with step authors contracted to check the signal between units of work and keep side effects idempotent upserts; the **attempt cap gates takeovers, not just retries** (R14), because a row stuck `claimed` by a dead worker was otherwise re-claimed forever with its side effect re-invoked each tick; and a step must **verify its own post-condition rather than trust a call that returned** (R19) — the intel orchestrator is best-effort by contract and never throws, so the step reads the row it should have written and reports `pending` when there is none. `pending` is a precondition failure, not an attempt: it costs nothing and retries next tick. Fingerprints are checked BEFORE the cap so that drift always revives a spent row — the alternative made a step that failed five ticks terminal forever even after its inputs changed.
  - **The newsletter rescan is resumable and never re-buys work (R20, R21, R22).** The global bogey scan walks unscanned articles once and stamps a per-article marker; an event armed afterwards would never see those numbers, so the rescan re-reads a bounded recent window for ONE armed event through a pure per-event path that never touches the global marker. Every (event, article, extractor version) attempt is a ledger row claimed BEFORE the model call, so a crash leaves a stale claim the next tick takes over instead of an invisible gap, capped by attempts. Three rulings shape the cost: a pair the global scan already extracted for this event is **banked from the existing bogey row with no model call** (R20); newsletter bogeys are read back **ordered by the article's issue date** with the upload stamp as fallback, so a preview block that shows only the first few rows shows the newest issues, not the oldest (R21); and each pass has a **soft budget** — a bounded number of model calls and a wall-clock limit both strictly inside the runner's hard deadline — after which it returns `pending` and resumes next tick, because a hard-deadline `failed` costs an attempt and, repeated, would retire the step (R22).
  - **Snapshot v11 and the Worker resolver.** The nightly snapshot reads everything in one transaction and records `armedGeneration` (the outbox maximum observed at that read — a watermark, not a count) alongside `armedEvents` and the per-bogey vendor EPS. The Worker's `effectiveCalendarEvents` starts from the snapshot's calendar rows, applies the armed projection, and applies the KV delta only when its generation is strictly greater than the watermark; a delta entry that matches an existing snapshot row overwrites **only the fields the projection genuinely owns**, because blanking the snapshot-only columns would kill the consensus fallback, the reporters table and the enrichment context. A snapshot at v10 or below ignores the delta and degrades to exactly today's held-plus-watchlist behaviour. The push gates were not touched on either side.

  - **R-C4 — pooled window, not anchor-ordering.** The effective window pools both terms per spec §4.3 — start = min(release−10m, forced−60m), end = max(release+45m, forced+90m, extension) — rather than clamping a late forced term to the scheduled term's own (narrower) start. Mutation-tested: reversing the registration order fails loudly (an FK error) rather than corrupting anything.
  - **R-C8 — a settled pass aborts its own signal.** When an acquisition pass settles, the scheduler aborts that pass's `AbortSignal` so no straggler road is left holding a concurrency slot. Consequently, anything that must outlive the pass — a go press's own delivery and DB writes, the post-commit prepare kick — is deliberately NOT linked to a pass signal, only to its own controller.
  - **R-C9 — default sleep timers are `unref`'d.** The scheduler's default `sleep` seam unrefs its timers so a cadence sleep, a wake wait, or the body-hold watchdog never holds the process open at shutdown. `SchedulerSeams` itself was not widened to carry this — it lives in the default implementation only, at no cost to correctness.
  - **R-C10 — a wake reason is informational only.** Whatever reason woke a pass (`cadence` / `burst` / `go` / `stranded`), the loop always runs a go-dispatcher tick and re-evaluates every print's effective window on ANY wake — so a user's go press remembered behind a `burst` wake is still acted on at once, never swallowed by a less-urgent reason. Reason precedence for logging purposes only is `go > stranded > burst > cadence`.
  - **R-C11 — `runForcedPass(db, printId, signal?)` is the contract.** The optional third parameter is deliberate: a go claim lost mid-acquire (a takeover, or a merge that re-homed the request) must abort the in-flight fan-out pass through the CALLER's own controller, composed with the scheduler's pass signal via `AbortSignal.any` — never the pass signal alone. Caveat carried into the docs: a call that JOINS an already-running coalesced pass cannot cancel that pass this way — its signal reaches only a pass it actually starts.
  - **R-C15 — a press that arms the event at the print minute takes NO IR baseline.** The `ir_baseline` step exists to record what the newsroom already carried *before* the print. Slice C added a press that arms AT the print and enqueues that step in the same transaction that stamps `forced_open_at`, so the step would have recorded tonight's release as history — and every runtime the watcher builds seeds its seen-set from `print_watch_ir_seen`, so the stored-IR-page road would have been blind for the night, silently ("ok — N matching links, 0 new") and across restarts. The step now reads the print row at RUN time and, once `effectiveWindow` has opened, completes as a no-op with a note: `done`, never `failed`, never a marker or a link row. That is slice B's own designed fallback — "no baseline (armed late) — period gate filtering". The guard is `now >= start`, not "contains now": a closed window has had the release on the page for even longer. Rejected: a `baseline_recorded_at < forced_open_at` check on the watcher side (needs a column, and the step-side guard is the honest place).
  - **R-C16 — the go dispatcher reconciles when it finds work it cannot place.** `wakePrintWatch` is in-process, so a press or an extension from another process reaches the lease owner as a ROW and nothing else; the tick's "no runtime here, skip" guard made the "picked up within 2 s" promise true only for prints that owner had already reconciled — an event the press itself armed, or one dated outside ±1 day, waited on the panel's 60-second ensure (only while a Today tab is open) or the 15-minute sweep. The tick now spends ONE `ensurePrintWatch` on takeable work it cannot place, and on a live forced window with no loop behind it, then re-reads. Latched twice: a memo keyed per go row and per print, so work that stays unplaceable never re-sweeps every two seconds, and a re-entrancy flag, because `ensurePrintWatch` ends with its own dispatcher tick.
  - **R-C17 — a disarm after a press ends the forced watch; the user's disarm wins.** The stale-print pass used to skip any print with a live forced window ("the press armed it"). What that earlier finding actually protected against was the ±1-day DATE scope, and slice C already fixes that by re-fetching the forced prints' events through the flag-joined query — so a still-armed forced print never reaches the skip. The only prints it could still catch were the ones whose flag the desk had just REMOVED, i.e. it overrode the disarm and kept polling every road for 90 minutes with no control to stop it. Deleted.
  - **R-C18 — losing the LEASE mid-go requeues the request; it never finalises `done`.** A lost CLAIM means someone else is running this request (write nothing). A lost LEASE means nobody looked: `runForcedPass` throws `WatcherLeaseLost` — including when the lease moves mid-pass — and `runGoRequest` puts the row back to `queued` with its attempts and partial reports intact, so the new owner's dispatcher runs the fan-out. Acquisition itself was never lost (the new owner's cadence loop polls the same window within 10 s), but "DJ: skipped (lease lost)" as the press's final answer is a permanent lie on the card.
  - **R-C19 — a cancellation never charges the IR link's 3-strike budget, and the ROAD'S SIGNAL is what says it was cancelled.** The budget is shared across the page fetch and every link of the road, so three cancelled polls at the print minute would have retired tonight's link permanently ("1 link(s) retired after 3 refusals") with no way back. The lane rethrows a cancellation to its page-level catch, which reports it without charging any link; only a real refusal — a refused ingest, an unreachable link, an unparseable one — spends a strike. The test cannot be the ERROR'S NAME: a cancellation surfaces as two shapes depending on where it lands — the scheduler's `AbortedError` (name `AbortError`) when the fetch was still queued for a host token, and `UrlFetchRefused("… aborted by the caller …")` when it was already in flight, which is the common case on a slow newsroom and the one the finding was written about. `isAbortError(err) || road.signal.aborted` covers both and any future shape, and errs safe: a genuine refusal that coincides with a cancellation costs the link nothing.

- **Auto-expansion is transition-based and first-load-silent**; a manual toggle wins and is remembered per PRINT, so a date correction that re-homes a row onto a new print does not inherit the old preference. **Corrected during the build:** the open/closed decision is made ONCE per print inside the provider, keyed by event id, not once per responsive twin — the first shape let the desktop grid row and the mobile card disagree the moment a manual toggle happened at the 1280 chat-rail-open boundary, where both twins can mount. Only the currently visible twin renders the body.
- **Retirement is a RENAME.** `print_watch_lines`' PK is `(print_id, metric_id)`, so a retired row takes `<metric_id>~retired~<n>`. Slice B declared the `retired` state and never produced one; `recompileContracts` is its first producer. **A branch review Critical, closed before this landed anywhere live:** the rename must also re-tag every candidate inside the retired row's own `candidates_json` to the new id (`retagCandidatePool`) — `collectCandidates` has no state filter, so without the re-tag a later document repeating the OLD reading would turn the fresh line green under a definition it was never measured against. The bug was live the moment `saveBogeyWithRecompile` started calling `recompileContracts` on every save, in the same session it was caught.
- **The prepare status line reads `GET /api/earnings/worksheet?eventIds=`,** because `GET /api/print-watch/status` exposes no prepare state. A `pending` `ir_baseline` on a symbol with no stored IR page is the normal resting state and renders as "waiting on an IR page" (`PrepareStatus`), never as stuck.
- **`PUT /api/print-watch/sources` gets its first UI** (`IrPageField`) — slice B shipped the route with no caller. Slice F's only other touch to that route file is a new, separate, read-only `GET` for the field's initial value; `PUT` is untouched.
- **The promote control stays visible on both sides of the E/F merge boundary.** Read literally, the plan puts promote inside `PrintOutputs`, which renders nothing until slice E's `outputs` field exists — which would have deleted a working control from the sheet for the whole window between F merging and E merging, exactly the window that contains live prints. Shipped instead: `PromoteButton` is exported from `PrintOutputs.tsx` and rendered directly by `LivePrintRow` whenever `outputs` is absent, and by `PrintOutputs` (via a `promote` prop) once it is present — one control, two render sites, same three 409 confirms.
- **A mutating control's busy state clears only once its refetch has LANDED.** The poll controller's `refresh`/`refreshAll` return a `Promise<void>` that resolves after the run has actually settled (applied, dropped as stale, aborted, or errored) — never merely after the request is issued — so `onChanged()` cannot return before the row it just mutated has re-rendered. Without this, an accept button re-armed while the sheet still showed the pre-mutation value, on the surface where the desk accepts machine-read numbers against a clock.
- **The Δ column is masked whenever the bogey is** (TODO ruling (ii), 2026-09-04): a masked bogey beside a clear Δ is recoverable by division. Shipped further than the plan anticipated: under privacy mode the Δ cell renders a NEUTRAL colour rather than green/red, because a coloured Δ beside a masked bogey still tells a shoulder-surfer whether the print beat the desk's number even with the figure itself hidden. This is the faithful reading of the prior masking ruling, which spoke about the value, not the colour — it changes what privacy mode looks like on this surface and is flagged for confirmation (`docs/plans/TODO.md`).
- **The bogey content-column TODO closes with a guard, not a merge:** `CONTENT_COLUMNS` gains `extra_metrics_json` and `tests/repo/bogey-content-lists-agree.test.ts` pins `CONTENT_COLUMNS ⊆ BOGEY_CONTENT`. The two lists keep their different meanings.
- **F adds no migration** (spec §5) and never edits `lib/earnings/**`, `lib/calendar/**`, `lib/digest/**`, or the Worker — slice E owns those. The one exception on the print-watch surface is a single new read-only `GET` added to `app/api/print-watch/sources/route.ts` for the IR-page field; every other `app/api/print-watch/**` route is untouched, and the two slices otherwise share no file.
- **A `"use client"` boundary guard allowlists three provably pure server-tree modules rather than banning the trees outright.** `tests/repo/hub-live-client-boundary.test.ts` lets a Today client file value-import `@/lib/earnings/actuals-validation`, `@/lib/earnings/format-bogey-fields` and `@/lib/calendar/date-utils` — the three such imports that already existed on `main` — and separately asserts, TRANSITIVELY, that each stays free of `node:`/`better-sqlite3`/`@stoqey/ib`/`@/lib/db`/`@/lib/ai/` imports. The guard's real target is `@/lib/earnings/cockpit-stages`, which drags `@stoqey/ib` across the boundary; a blanket ban that red-lit three clean modules would have been deleted by the first person it inconvenienced. `BogeysEditModal.tsx` separately re-declares the five-field `RecompileReport` display shape rather than `import type`-ing it from `@/lib/print-watch/recompile` — the guard is a text scan that cannot see `import type`, so the type-only import still reds it; re-declaring follows the same precedent `hub-live/types.ts` already set for `@/lib/queries/earnings-cockpit`.
