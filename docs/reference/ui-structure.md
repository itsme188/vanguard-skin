# UI Structure

## Security Detail Page

- Route: `/dashboard/security/[id]` — hub page for a single security
- Shows: chart (SecurityChart), positions (cross-account), tax lots (open + closed), transactions, notes, events, factor exposure, transcripts
- Every symbol in the app links here via `SymbolLink` component
- Watchlist button toggles add/remove with star icon
- `lib/queries/security-detail.ts` — consolidated queries calling existing sub-queries


## Tab Structure

- **6 desktop tabs (post-redesign 2026-04-30):** Today | Accounts | Analysis | Research | Charts | Import. Cuts from the prior 9: Overview → absorbed into Today; Holdings → absorbed into Accounts cross-account section (`/dashboard/accounts?id=all#holdings`) + Cmd+K ticker-jump; Calendar → absorbed into Today week-ahead block. Old routes redirect (`/dashboard/overview`, `/dashboard/holdings`, `/dashboard/calendar`, `/dashboard/levels/review`) — kept as 5-line redirect stubs to cover external bookmarks (iPhone home-screen shortcuts).
- **Today (post live-print-v2 slice F, 2026-09-04)** renders exactly six blocks, in order: the date header (+ Vanguard snapshot age, price-quality chip, Week ahead link) · the Portfolio strip · Today's releases (full width) · the **Earnings Hub** · the chat button · a ONE-LINE IBKR today snapshot (`<Count> names · <Money signed> today (<Pct>) · refresh · Accounts →`; the per-name list lives on `/dashboard/accounts`). Alerts, Nearby Levels, the Earnings Cockpit and the Live Print Watch panel are GONE from Today; Significant Moves and Momentum Pulse moved to **Analysis · Diagnostics** (above `TrustStrip`, below the view toggle).
- **Today's wording for dates and the day move (2026-10-08).** The label decisions live in `app/dashboard/today/basis-labels.ts` (words only, never a figure):
  - *Portfolio strip.* The change chip names the statement it compares against (`portfolioBaselineLabel`): one shared date reads "vs <date> statement"; when the accounts' baseline statements differ it names the range. Each account's baseline is its previous statement, which is not always the prior month-end.
  - *IBKR line heading.* It says "IBKR today" only when the measured session is today's Eastern date; an earlier session is named and an unknown one is "last session" (`ibkrSnapshotHeading`).
  - *IBKR line notes.* The move follows the one day-move rule (`lib/compute/day-move.ts`; see `conventions-detail.md`). Small counts after the figure say what was treated differently, each with a tooltip: names opened that session (measured from cost), names with no cost that were left out, names added to, names added to with an unknown cost, names changed since an older snapshot (the change cannot be dated, so the new shares are left out), and names without a prior close. Each count renders through `<Count>`.
- **An armed row after its print shows a read-only record (2026-10-08).** When an armed row has no live print and its event date is before today, `LivePrintRow` renders `PrintRecordView`: a window-closed header, the accepted and agreed figures with their source documents, and the output buttons. Accepting and promoting are closed. It reads `GET /api/print-watch/record`. Detail: `earnings-pipeline.md`.
- **Hub row expansion.** An armed row renders a full-width sibling under its `DesktopRow` / `MobileCard` — `LivePrintRow`: the standing pre-gate disclosure ("Pre-gate build — machine-read values; verify every number before accepting.") in its header, the print header, go controls + paste box, IR-page field, prepare status, road outcomes, the sheet, the first-pass read, and the output buttons. The pre-existing promote control is NOT one of those output buttons — it renders directly from `LivePrintRow` (`PromoteButton`) whenever the status payload carries no `outputs`, which is the whole branch until slice E ships its three output buttons, so promote never disappears from the sheet in the interim; once `outputs` is present, `PrintOutputs` renders the same control through a `promote` prop instead. The row is a plain BLOCK sibling, not a grid span: `.earnings-hub-desktop` is a block container and the CSS grid lives on each row. The OPEN/CLOSED decision itself is made once per print inside the `EarningsHubLive` provider, keyed by event id rather than by the DOM node rendering it, so the desktop grid row and the mobile card share one decision and one clock; only the twin that is actually visible (`offsetParent !== null`, re-measured on resize and on the chat-rail toggle) renders the expanded body. Auto-expansion is transition-based (`hub-live/expansion.ts`) — entering `window_open`/`acquired`, a newly forced window, or a new go request; a first load never auto-opens, and a manual `expand`/`collapse` overrides and is remembered per print in `localStorage["vgs:print-expanded:<printId>"]`. A live print whose event is NOT in the rendered week appears under a **Live prints outside this week** block (`LivePrintsOutsideWeek`) at the foot of the Hub, so a forced window on a stale event is never invisible from Today.
- **At 1280 with the chat rail open the Hub is already the MOBILE layout** (`app/globals.css`: `768px–1535px` + `html[data-chat-rail="open"]` hides `.earnings-hub-desktop`). The rail reserves `--chat-rail-width` (480px, 720px expanded) as `padding-right` on `.chat-rail-reserve` at ≥1280px, leaving ~752px. Because the expansion's open/closed state lives once in the provider (see above) rather than per responsive twin, switching between the desktop grid and the mobile card at this breakpoint changes only which twin RENDERS the body, never whether it is open.
- **One controller.** `EarningsHubLive` is a client provider wrapping the Hub's SERVER-rendered rows; it owns every poll (status hot 2s / cool 30s following the print state, `/ensure` every 60s, the cockpit refresh, the worksheet prepare read), drops responses whose generation is stale, and aborts everything while the tab is hidden. Every mutating control awaits `onChanged()`, and `onChanged` itself awaits the underlying refresh(es) until they LAND — not merely until they are issued — so a busy control cannot re-arm before the row it mutated has actually re-rendered. The 1-second countdown clock is gated on any live print OR an upcoming release across the WHOLE rendered week, never on today-only data, so it does not freeze on a day with no release due today.
- **Chat** is persistent right rail on desktop ≥1280px + full-screen overlay on mobile (ChatDrawer.tsx). Toggle via header button or Cmd+J.
- **Cmd+K** is global ticker-jump — typing a symbol routes to `/dashboard/security/[id]` (replaces the prior global-search role).
- **Alerts** inbox is unified (`/dashboard/alerts`): fired alerts + pending newsletter-extracted levels in one auto-promoted stream. Header bell `<NotificationBell>` shows combined count; old separate `AlertsBell` + `ReviewBell` deleted.
- **NotesAmbient** overlay (`⌘;`, keyboard only — the floating button was removed 2026-09-04 per QA ruling; on mobile, notes are reached through the bottom-nav "Notes" entry, i.e. the Notes page) is accessible from any tab; saves to localStorage drafts and posts to Notes.
- **Reconciliation** merged into Accounts tab as collapsible section.
- **Notes** renamed to **Research** (redirect from /dashboard/notes)
- **Research** tab has 3 views: Notes (default) | Feeds | Documents (newsletter articles + uploaded PDFs). Trade Reviews relocated to Analysis sub-view in Phase 5.
- **Analysis** tab has 5 sub-views: Performance (TWR + XIRR + period selector) | Classification (default) | Factor Exposure | Trade Reviews | Defense (hedging analysis, added 2026-07-05). Use `?view=performance` / `?view=trade-reviews` / `?view=defense` for the sub-views; `?mode=factors` for the Factor Exposure view (kept the legacy `mode` param for backward compat).
- **Analysis remembers the last scope for the session (2026-10-08).** Leaving Analysis and coming back through the nav lands on the account scope last chosen. The memory is `sessionStorage` only (`lib/ui/analysis-scope-memory.ts`, key `vgs:analysis-scope`; hook `use-remembered-analysis-scope.ts`, used by `TabDropdown` and `MobileBottomNav`), so a fresh launch still opens on each view's ruled default. On an Analysis page the live URL scope wins. Blocked storage falls back to no memory.
- **Each Diagnostics card says what its percent is of (2026-10-08).** With a short in the book the cards use different denominators, and no figure was changed to hide that: the Breakdown is a percent of net value (longs minus shorts), Concentration and the risk top-five are a percent of gross exposure, the factor heatmap weight is a percent of net value, and the position-risk weight is a percent of long holdings. The strings are single-sourced in `lib/analysis/percent-bases.ts`. The three catch-all geography buckets (International, International Developed, Global) carry a short definition from the same file; the stored bucket name is never rewritten. Significant Moves follows the scope selector, reads completed sessions only, and names both days it compares.
- **Performance periods.** One, three and five years end at the last statement and the caption names the end date; year to date and All run to today (`lib/compute/performance-window.ts`; see `conventions-detail.md`).
- **Performance reads the whole scope (2026-10-08, second half).** The money-weighted return, the risk tiles and the equity curve read every account in the selected scope, not the first one. The curve starts at the scope's first statement (`lib/compute/equity-curve-floor.ts`), and the caption prints the start date the return really uses. No time-weighted return computation changed; the one-day difference between the two start-date branches is an open owner question (see `conventions-detail.md`).
- **Trust strip: "Sectors classified" is the time option sectors were last CHECKED (2026-10-08).** A full sync or an Auto-Classify run records it with or without work to do; a run that failed part-way does not move it. Data Health gains a read-only list of held, live options whose underlying has no usable sector, with what is missing and where the option's sector came from.
- **Fixed Income card (2026-10-08).** It shows the duration the scenario rate leg would use for each bond, marks a derived one as an estimate, and lists a bond it cannot model as "not modelled" with no figure. The weighted duration covers only the modelled bonds and the card says how many were left out.
- **Research · Feeds: the digest Preview opens on the Send panel's window (2026-10-08).** The two share one choice (default "Today's articles"; `app/dashboard/components/digest-window-choice.ts`). The digest catch-up banner says "nothing new to send", with no Send button, when the scheduled run looked and found nothing (`lib/digest/catchup-banner.ts`).
- **Questions and chips (2026-10-08).** A yes/no question uses the app dialog (`useConfirmPrompt`), never a native browser prompt. A `<Chip>` is one line unless the caller passes `wrap`; chip tones are pinned for contrast in both themes. Detail: `conventions-detail.md` §L.
- **Hub date chip: Save over a web-verified time asks first (2026-10-08).** The release-time popover asks through the app dialog before a Save replaces a web-verified time, shows the time stored on the row before the ticker's resolved time, and no longer pre-fills a standing time the app does not use.
- **Data Health opens with the confidence score (2026-10-08).** `/dashboard/data-health` shows the overall score, the badge's own wording and any cap reason at the top, from the same read the header badge makes. This is also the phone's only view of the score, since the header badge is hidden below `md`. The wording helper is a plain module (`lib/ui/data-confidence-level.ts`) because a server page cannot call a function from a `"use client"` file.
- Old routes (/dashboard/notes, /dashboard/reconciliation, /dashboard/chat) redirect to new locations
- **Tab-subview dropdowns (desktop)**: tabs with `subviews` in `nav-tabs.ts` (currently Research + Analysis) render a caret ▾ next to the label; clicking opens `TabDropdown.tsx` — a menu of subviews with keyboard nav (ArrowDown opens, Arrow keys/Home/End cycle, Enter selects, Escape/outside-click close). Menu uses `position:fixed` + `getBoundingClientRect()` to escape the parent `<nav>`'s `overflow-x-auto` clip (absolute positioning gets silently cut off). Mobile keeps the in-page pill toggle (`ResearchViewToggle`, `AnalysisView` mode toggle — both gated `md:hidden`). `TabDropdown` reads `useSearchParams()` so it's wrapped in `<Suspense>` inside `TabNav.tsx` with a plain-`<Link>` fallback — required to keep static pre-rendering working for dashboard pages without `force-dynamic`.


## Mobile Responsive

- **Bottom nav** (`MobileBottomNav.tsx`): 5 icons — Today, Research, Chat (gold center), Notes, Analysis. `md:hidden electron:hidden`. Notes maps to `/dashboard/research?view=notes` (Notes is a sub-view of Research, promoted to a first-class mobile destination).
- **Desktop tabs** hidden on mobile (`hidden md:flex` on TabNav `<nav>`). Maintenance tabs (Accounts, Charts, Import) only in desktop nav.
- **Chat**: full-screen overlay on mobile (`fixed inset-0`, slide-up via `translate-y`), 480px side drawer on desktop. Uses `useIsMobile` hook + `toggle-mobile-chat` DOM event.
- **Chat right-rail collapse (xl+)** — `ChatDrawer.tsx` exposes a chevron at the rail's top-right that hides it; layout reservation (`xl:pr-[480px]` previously) is now driven by the `--chat-rail-width` CSS variable + the `chat-rail-reserve` class on the dashboard layout div. State persists via `vgs:chatRail` localStorage; an anti-FOUC script in `app/layout.tsx` mirrors it to `<html data-chat-rail="open"|"collapsed">` before React hydrates so first paint matches. Header `ChatToggleButton` now uses `chat-toggle-rail-aware` — visible at xl only when the rail is collapsed (CSS attribute selector in `globals.css`). When components need to respond to the rail state (e.g. `EarningsHub` switching between desktop grid and mobile cards at `<2xl` if rail open), use the `[data-chat-rail="open"]` attribute selector — no JS state needed; cascade flips instantly when ChatDrawer toggles.
- **Header**: simplified on mobile — only Title + Search + Settings. DataConfidenceIndicator, TwsStatus, ChatDrawer toggle, AppVersion hidden via `hidden md:flex`.
- **ChatDrawer rendered at layout root** (not inside header) so mobile full-screen overlay works. Do NOT wrap in `hidden md:flex`.
- **Breakpoint**: `md:` (768px) separates phone from tablet/desktop. Mobile-first defaults.
- **Safe area**: `pb-safe` utility in globals.css, `viewport-fit=cover` meta tag for iPhone notch/home indicator.
- **Remote access (post #35 cutover, 2026-08-14)**: the Next server binds loopback-only (`127.0.0.1:3099`) — no LAN/mesh interface, permanently (spec §5.3 invariant, `docs/superpowers/specs/2026-08-14-packaged-app-trust-boundary-design.md`). The iPhone reaches the dashboard via a named Cloudflare Tunnel to `app.myportfoliodesk.com`, gated by Cloudflare Access in front and an app-level login (DB-backed session + CSRF) behind it — Access approval alone grants nothing; the app still requires its own authenticated session. The Cloudflare Mesh / `100.96.0.1:3099` path described in earlier revisions of this doc is retired.


## Benchmark & Risk

- Benchmark prices stored in `benchmark_prices` table (migration 014), separate from portfolio `prices`
- Benchmark sync requires TWS connection; falls back to `ohlcv_bars` then `prices` table for cached data
- TWS `getHistoricalData` requires `conId` in contract for reliability — symbol-only contracts time out
- `lib/tws/benchmark.ts` auto-resolves conId via `getContractDetails` for unknown benchmark symbols
- Risk metrics computed from `daily_valuations` — no external data needed
- Sharpe ratio uses `getRiskFreeRate(db)` (`lib/queries/risk-free-rate.ts`, a cached fetched rate; 4.5% is only the default when none was ever fetched)
- Recharts `formatter` on Tooltip needs untyped params: `(value) => [formatFn(Number(value)), label]`
- Recharts `minTickGap={40}` on XAxis prevents duplicate labels with dense daily data
