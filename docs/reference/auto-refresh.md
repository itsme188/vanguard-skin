# Auto-Refresh & Data Confidence

## Auto-Refresh & Data Confidence

On TWS connect (auto or manual), `lib/tws/auto-refresh.ts` orchestrates a 6-step pipeline:
1. `syncPortfolio()` — positions + account values + live prices (15s)
   1.5. `purgeExpiredOptionHoldings(db)` — sweeps holdings for expired options (1-day grace). Statement imports never zero-out positions that simply disappear from the next snapshot, so expired options would otherwise linger forever and surface in briefings / cross-account rollups (see `lib/mutations/expired-options.ts`).
   1.6. `purgeClosedOptionHoldings(db)` — sibling to 1.5 for explicitly closed options.
   1.7. `purgeMaturedBondHoldings(db)` — sibling for matured T-bills + bonds (1-day grace). Same root cause as 1.5: statement imports never zero-out maturity-disappeared rows, so matured bonds linger in scenario rate-shocks + fixed-income analytics until manually cleared (see `lib/mutations/matured-bonds.ts`). Also runs as a post-commit hook in `commitImport` for holdings-snapshot sources (`vanguard-pdf`, `vanguard-export`, `vanguard-holdings`, `ibkr-holdings`, `ibkr-activity`) so PDF imports clean up the same day.
   1.8. `reconcileClosedEquityHoldings(db)` — sibling to 1.5–1.7 for closed **stock/ETF** positions, but **snapshot-diff** (not attribute/transaction) based. Equities have no expiry/maturity AND the local trade ledger is often incomplete (statements lag), so the authoritative "is this closed" signal is the broker/statement snapshot itself: any equity absent from an account's latest *full* holdings snapshot (newest `as_of_date`) gets a `quantity = 0` row at that date. **Non-destructive** (preserves cost-basis/history), **self-healing** (a later real sync writes a newer row that wins), **idempotent**. **Shrink guard**: skips an account whose latest snapshot is empty or `< 50%` of the prior snapshot's position count, so a partial/failed TWS sync or under-extracted Vanguard PDF can never wipe the book (under-reconcile self-heals next cycle; over-reconcile would be unrecoverable). Also runs as a `commitImport` post-commit hook (same holdings-snapshot sources as 1.5–1.7). Shipped 2026-06-02 (`58479c3`) after a TWS sync left 35 phantom IBKR equities; see `lib/mutations/closed-equity.ts`. Surfaced via the IBKR Claude connector reconciliation — connector assessment at `docs/plans/2026-06-01-ibkr-connector-assessment.md` (Tiers 2/3 = TWS-independent + cloud IBKR Web API data paths, deferred).
2. `enrichSecurities()` — TWS contract details for unenriched securities (rate-limited, skipped if none)
   2.5. `classifyOptionSectors(db)` — sector-classifies blank-sector held-option underlyings (free SQL pre-check; Claude only when there's work). Also runs in `POST /api/compute/classify`.
   2.6. `classifyFactors(db)` — factor-classifies new securities + option underlyings (incremental by construction; early-returns before any Claude call when fully classified). Was manual-only — new positions silently degraded scenarios/heatmap/tilts (2026-06-09).
3. `fetchSnapshotPrices()` — current prices for ALL held securities (~2 min, NOT rate-limited)
4. `computeDailyValuations()` — recompute with fresh prices (instant)
5. `fetchBenchmarkPrices()` — benchmark ETFs, incremental (parallel with steps 3-4)
6. `detectAndFireAlerts()` + `generateSuggestionsForPendingAlerts()` — scan active `security_levels` against fresh prices, insert `level_alerts` + Claude one-sentence recommendations

- **Sync state**: `lib/tws/sync-state.ts` — globalThis singleton tracking status, phase, progress. UI polls `GET /api/tws/sync-status` (3s during sync, 30s when idle).
- **Mutex**: `isSyncing()` prevents concurrent runs. Second call returns immediately.
- **Background refresh**: `lib/hooks/useAutoRefresh.ts` triggers quick refresh (snapshot + valuations only) every 30 min while connected. Configurable via `refreshIntervalMinutes` in Electron settings (0 = disabled). **Disconnected path (R1, 2026-07-03 `42484cf`; R1b follow-ups 2026-07-07)**: when TWS is NOT connected, the same timer fires the route's IBKR Web API fallback — gated by `lib/tws/webapi-refresh-gate.ts` (Mon–Fri 9:30–16:00 ET wall-clock via Intl — never the local clock — + `isMarketClosed` holiday skip + localStorage `vgs:lastWebApiRefresh` debounce as the cheap client-side first gate, since the in-memory ref resets per page mount). Broker-only pricing by user decision — never introduce a third-party price source for held securities on this path. **R1b**: `refreshIbkrHoldingsFromWebApi` now (a) prices held options + bonds via the snapshot `priceOnly` tier, (b) runs the shared `lib/alerts/scan-cycle.ts::runLevelScanCycle` (same cycle as auto-refresh Step 6 — reconcile cloud-fired → detect → mac-recent-scan marker → suggestions) so MA-based levels fire away from home, and (c) reports through sync-state with `lastSyncVia:'ibkr-webapi'` (+ `isSyncing()` mutex); TwsStatus shows "Web API synced" when disconnected.
- **Data confidence**: `lib/queries/data-confidence.ts` scores 5 dimensions (price freshness 40%, holdings recency 25%, cash accuracy 15%, enrichment 10%, valuation coverage 10%). `DataConfidenceIndicator.tsx` replaces `DataFreshness.tsx` in header — shows score, colored dot, popover with dimension bars and actionable fix buttons. Polls `GET /api/data-confidence` every 60s.
- **Data quality labeling**: Migration 026 adds `data_quality` column to `daily_valuations` (`live`/`recent`/`estimated`/`computed`). Set by `computeDailyValuations()` based on price staleness. Account cards show "(est.)" for stale data; portfolio total shows "~" prefix when estimated.
