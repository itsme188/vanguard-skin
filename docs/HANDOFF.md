## 3. Open concerns, rejected approaches, decisions

- **`headline-basis.ts` infers something the schema does not record.** `calendar_events.actual_value` carries no basis, so the module reconstructs it: an unstamped row is the vendor feed; a stamped row is matched against the print-watch sheet's accepted lines (adjusted first, so a promote that fell back to GAAP reads as GAAP); with no sheet, or no line matching the stored figure, it returns adjusted on the strength of the 2026-10-08 ruling that a worksheet or hand-entered figure is "adjusted". That last fallback is the soft spot: a hand-entered GAAP figure will be labelled adjusted and will therefore score against an adjusted bogey. It is the ruled behaviour, and the tolerance for the match is 0.005, but it is an inference and worth a second reader.
- **Worker fallback scoreboard cannot know basis — queued for a later slice, deliberately not fixed tonight.** The R2 snapshot carries no print-watch sheet, so the cloud composer has nothing to read a basis off. The Mac is the source of truth here and the Worker is fallback-only, so the gap only shows when the Mac has missed its window. Recorded in the `docs/DECISIONS.md` addendum and in TODO. Two other things named there as unknowable today: the callout's `vs guide` text (free-text guidance) and the vendor EPS consensus itself (basis unspecified, treated as adjusted by the rule above). **No Worker deploy was part of this bundle** — nothing in it touched `workers/cron/`, so Mac/Worker parity is unchanged.
- **Two pre-existing runtime issues seen in the server log, neither from this bundle, neither fixed:**
  1. `cloud-reconcile` writes an `[server:err]` line **every 15 minutes, indefinitely**, for one earnings event whose cloud revenue actual is the vendor's rounded rendering while the local one is exact. The reconciler is behaving correctly — it keeps the local value, the stricter reading of "a cloud actual fills a missing local actual and never replaces one". But the comparison is made between two differently-formatted renderings of the same print, so it can never converge, and the line will repeat for as long as the event stays in the 14-day lookback. Worth a numeric tolerance or a log-once: as it stands the noise would mask a real reconcile mismatch.
  2. `print-watch` logged `first-pass read … failed (cites)` three consecutive times for one print (23:29–23:34). That is print-watch refusing to promote a figure it could not bind to a cited line — the safe direction, and consistent with R1 — but that print got no first-pass read.
- Rejected: running `verify.sh full` concurrently with the Electron build. `tests/coord/` exercises the same named locks (`integration`, `deploy`, `app-3099`) the deploy holds, which is a false-failure source; the 2026-11-04 session also saw `tests/tws/auto-refresh-integration.test.ts` time out purely from build contention. The suite was started only after the deploy released its locks.
